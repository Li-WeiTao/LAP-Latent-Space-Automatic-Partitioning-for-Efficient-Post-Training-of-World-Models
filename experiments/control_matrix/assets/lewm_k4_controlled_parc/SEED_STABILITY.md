# LeWM K=4 partition-seed stability

## Scope

This compares saved deployment partitions for partition seeds 0, 1, and 2.
The four previously audited methods were not refitted. Random Voronoi had no
LeWM K=4 partitions, so its three seeds were generated once per task from the
same frozen latent cache using the existing `fit_partition.py` entry point;
no predictor was trained or evaluated. Within each task, all three label arrays
refer to the same latent-cache hash and the same ordered sample IDs. We
computed the adjusted Rand index (ARI) for seed pairs 0–1, 0–2, and 1–2 on
the complete saved label arrays. ARI does not depend on arbitrary region-ID
permutations. Each table cell averages the three seed-pair ARIs; the final
column averages the four tasks with equal task weight.

| Rank | Partition method | TwoRoom | PushT | Reacher | Cube | Four-task mean |
| ---: | --- | ---: | ---: | ---: | ---: | ---: |
| 1 | Spectral | 0.934 | 0.613 | 0.814 | 0.615 | **0.744** |
| 2 | K-means++ | 0.255 | 0.344 | 0.471 | 0.266 | **0.334** |
| 3 | GMM | 0.347 | 0.246 | 0.199 | 0.490 | **0.321** |
| 4 | Controlled PARC | 0.138 | 0.235 | 0.167 | 0.084 | **0.156** |
| 5 | Random Voronoi | 0.020 | 0.027 | 0.014 | 0.008 | **0.018** |

Spectral is highest and Random Voronoi is lowest on every task. K-means++
and GMM are close in the four-task mean and swap order across tasks. Controlled
PARC is the least stable of the four fitted methods on every task, and does
**not** pass this preliminary reproducibility check for stable K=4 regional structure.
This is a statement about partition stability, not a proof that the labels
contain no dynamics information or a ranking of planning success. The
fit-to-deployment label disagreement recorded in the PARC manifests is a
separate diagnostic and is not included in these ARI values.

## Machine-readable evidence

- `partition_seed_stability.json`: Controlled PARC, including all three
  pairwise ARIs, Hungarian-aligned agreements, contingency tables, source
  paths, cache hashes, and per-seed cluster counts.
- `spectral_seed_stability_reference.json`,
  `kmeanspp_seed_stability_reference.json`, and
  `gmm_seed_stability_reference.json`: identical audit for the three
  previously audited reference methods.
- `random_voronoi_seed_stability_reference.json`: identical audit of the
  newly generated K=4 random Voronoi deployment labels.
- Analysis code: `experiments/control_matrix/analyze_partition_seed_stability.py`.

The read-only audit for Random Voronoi is reproducible with:

```bash
.venv/bin/python experiments/control_matrix/analyze_partition_seed_stability.py \
  --repo . --tasks tworoom,pusht,reacher,cube \
  --method random_voronoi --num-clusters 4 --seeds 0,1,2 \
  --output experiments/control_matrix/assets/lewm_k4_controlled_parc/random_voronoi_seed_stability_recheck.json
```

The audit entry point refuses to overwrite an existing JSON result. The
Random Voronoi partitions themselves were generated by the existing
dataset-parameterized `fit_partition.py` with `--method random_voronoi`,
`--num-clusters 4`, `--seed` in `0,1,2`, and the same per-task latent cache
recorded in each manifest. All five methods use identical ordered sample IDs
within each task, not merely identical sample counts and cache hashes.

The four-task means before rounding are Spectral 0.744197, K-means++
0.334295, GMM 0.320515, Controlled PARC 0.155990, and Random Voronoi
0.017505. All source labels were the saved
`experiments/<task>/matrix_k4/partitions/<method>/seed<seed>/cluster_labels.npz`
files. Existing partition, training, evaluation, and planning-result files
were not modified by this analysis.
